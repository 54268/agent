# 多智能体开放集辐射源识别：问题与思考汇总（精简汇报版）

## 当前总体判断

我们已经证明：**不同证据之间存在互补，通信也确实会影响决策；但“多个 Agent 都很强”“消息被使用”“最终指标高”，都不能直接证明多智能体协作本身有价值。**

目前真正需要解决的是：

> **怎样定义既有自主性、又彼此不可替代，同时还不能等价于完整算法的 Agent。**

---

## 一、目前遇到的主要问题



### 4. Agent 太大，会退化成“整个算法换了个名字”

曾经的 Prototype Agent 内部已经同时包含 raw、spectral、envelope、difference、complex、prototype、tail 等大量能力，本质上接近一个完整多视图系统。

### 6. Agent 太相似，通信就没有必要

WiSig 上曾出现 Temporal 和 Spectral 都很强，但错误样本高度重合，说明“两个 Agent 都强”不代表它们具有不可替代的能力。

### 1. 每个 Agent 都很强，不等于协作有价值

多个 Agent 各自准确率很高，但如果最后只是比较 confidence 或加权融合，本质上仍然更像多分类器/多专家，而不是真正多智能体。

### 7. Agent 太弱，所谓互补也可能只是随机错误不同

ORACLE 上 Spectral 一度训练集可以完全拟合，但 held-out 接近随机，此时看到的 rescue 不能直接解释为真正互补。

### 5. Agent 太死，也不像真正的智能体

后来把 Agent 固定成“Temporal 只能看时域、Spectral 只能看频域”，虽然边界清楚，但又把 Agent 做成了固定输入—固定输出的网络模块，缺少自主选择能力



### 2. 通信会影响结果，不等于通信产生了正收益

我们通过关闭消息、打乱消息证明了模型确实使用通信，但正常通信并没有稳定优于无通信模型，因此“消息有效”与“协作有效”必须分开验证。

### 3. 只靠 Router 判断“信谁”并不能解决问题

多轮 Reliability Router、B2、competence 等实验表明，confidence、entropy、margin 等信息很难稳定预测“哪个 Agent 真正更适合当前样本”。



。



### 8. WiSig 和 ORACLE 的有效证据并不一样

两个数据集虽然都可以输入短 I/Q，但采样环境、receiver、channel、CFO、session、对齐方式等可能不同，所以相同视图在两个数据集上的价值可能完全不同。

---

## 二、一个很关键的证据：同一套算法在两个数据集上自动选择了不同视图

Stage-5 Unified V4 使用同一套算法，但模型学习到的视图使用权重明显不同：

| 数据集 | 样本 | raw | spectral | envelope | diff | complex |
|---|---|---:|---:|---:|---:|---:|
| ORACLE | Known | 65.57% | 0% | 4.52% | 0.01% | 29.90% |
| ORACLE | Unknown | 39.65% | 0% | 15.55% | 0% | 44.80% |
| WiSig | Known | 4.65% | 8.52% | 5.54% | 3.74% | 77.55% |

这张表不是“数据集本身的信息比例”，而是**模型学到的视图使用权重**。

它说明：

- ORACLE 在当前表示下几乎不使用 pure spectral，主要依赖 raw + complex；
- WiSig 主要使用 complex，同时仍保留部分 spectral、envelope、difference；
- 同一套算法会根据数据自动改变有效证据组合。

因此：

> **“一个 View = 一个固定 Agent”可能本身就是不合理的。**

真正的 Agent 应该有一个明确目标，同时拥有有限的工具箱，并根据当前样本自主选择哪些工具有效。

---

## 三、目前得到的核心认识

前面的多轮实验虽然遇到了很多失败，但已经帮助我们排除了几条错误路线：

- 多个网络 ≠ 多智能体；
- 多个 Agent 都强 ≠ 协作有价值；
- 消息被使用 ≠ 通信有净收益；
- confidence Router ≠ 真正的协作决策；
- 一个包含全部能力的 super-agent ≠ 多智能体；
- 一个固定 View 的网络分支 ≠ 真正 Agent；
- Agent 不能太强，也不能太弱；
- 不同数据集不能假设固定证据始终有效。

---

## 四、现在重新理解“真正的 Agent”

下一版 Agent 不应该由“固定输入是什么”来定义，而应该由：

> **它要解决什么问题、拥有哪些私有知识和工具、它能否自主选择工具、能否主动求助、能否根据新信息修改判断。**

同时还要满足：

> **任何一个 Agent 都不能单独拥有完成整个开放集算法所需要的全部能力。**

因此更合理的是“中等粒度 Agent”：

- 内部可以调用多个相关工具；
- 可以自主决定哪些工具当前有用；
- 可以 abstain；
- 可以主动询问其他 Agent；
- 但不同 Agent 之间必须保留真实的知识和能力边界。

---

## 五、下一阶段方向

下一版不再继续按照：

> Temporal Agent / Spectral Agent / Prototype Agent

这种“一个视图一个 Agent”的方式设计。

更合理的是围绕问题目标设计，例如：

- **Signal Identity Investigator**：负责调查“当前信号更像哪个 emitter”，内部可在 raw、complex、envelope、difference 等有限工具中自主选择；
- **Hardware Impairment Investigator**：负责从硬件失真角度验证候选，可以自主选择 robust spectral、IQ imbalance、phase-noise 等工具；
- **Open-Set Examiner**：负责审查“最像某个 Known”是否真的属于该 Known，可以调用 prototype、tail、reconstruction、consistency 等开放集工具。

工具本身不是 Agent。

Agent 才负责：

> 选择工具 → 形成判断 → 判断是否缺证据 → 主动询问 → 根据新证据修改结论。

---

## 六、一句话总结

我们现在不应该继续在旧框架里反复调 Router 或通信参数，而应该利用前面所有失败经验重新定义 Agent：

> **既不能把整个算法塞进一个 Agent，也不能把每个小模块都拆成 Agent；真正需要的是有明确目标、有有限私有工具、有自主决策能力，并且彼此不可替代的中等粒度智能体。**
