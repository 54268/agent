# 下一阶段代码重构规划：从“固定分支”转向真正的自主多智能体

> 目标：吸收前面所有失败经验，不再继续在 Stage-8 Temporal/Spectral 固定分工上局部打补丁，而是重构 Agent 抽象，使 Agent 同时具备“自主性”和“能力边界”。  
> 原则：不把完整算法塞进一个 Agent，也不把每个细小模块都拆成 Agent。

## 1. 先冻结已有结果，停止继续在旧架构上深挖

保留并冻结：

- Stage-5 Unified V4；
- Stage-7 条件咨询；
- Stage-8 Temporal/Spectral 两轮结果；
- Agent-B v3 快速验证作为诊断实验；
- nested LCO、formal Unknown lock、provenance、same-seed、message intervention 等基础设施。

不要删除这些负结果。

它们后续是新方法设计的依据和消融基线。

但不要继续：

- 给固定 Spectral Agent 不断增加更多 spectral channel；
- 扫更多 Router loss；
- 扫 threshold；
- 上 PPO / QMIX / CommFormer；
- 提前做 formal multi-seed。

下一阶段新建：

```text
src/maros_stage9/
```

Stage-8 保持只读历史基线。

# 2. 重新定义 Agent 抽象

下一版 Agent 不再定义成：

```text
固定 Observation
    ↓
固定 Encoder
    ↓
固定输出
```

统一定义为：

```text
目标 Goal
+
私有工具箱 Private Toolset
+
私有记忆 Private Memory
+
当前信念 Belief
+
工具选择策略 Tool Policy
+
通信策略 Query Policy
```

每个 Agent 都执行一个小型循环：

```text
观察当前样本/黑板
    ↓
评估当前信念和不确定性
    ↓
选择一个或多个本地工具
    ↓
更新自己的候选判断
    ↓
决定：
REPORT / ASK / CHALLENGE / ABSTAIN
```

这一步是 Stage-9 与之前所有阶段最大的区别。

---

# 3. 第一版只做 3 个中等粒度 Agent

暂时不要做 5～8 个。

## Agent A：Signal Identity Investigator

目标：

> 从信号自身寻找支持或反驳 emitter 身份的证据。

允许的私有工具可以包括：

```text
raw temporal encoder
complex-IQ encoder
envelope encoder
local-difference encoder
short temporal patches
```

它不必每次全用。

Agent 内部学习：

```text
当前样本应该调用哪些工具？
```

例如 ORACLE 上可能偏 raw/complex，WiSig 上可能大量使用 complex。

禁止访问：

```text
enrollment tail
open-set memory
正式 Unknown detector
Agent B/C private state
```

因此它不能独立完成整个开放集算法。

---

## Agent B：Hardware Impairment Investigator

目标：

> 从硬件失真、相对频率结构和稳健物理统计中调查候选 emitter。

工具箱可以包含：

```text
robust spectral shape
segment-averaged spectrum
frequency-local contrast
spectral derivative/difference
IQ-imbalance descriptor
robust phase-noise descriptor
complex-frequency descriptor
```

重要变化：

> Agent B 不再等同于“Spectral View”。

如果 pure spectral 在 ORACLE 上无效，Agent B 可以把它权重降到接近 0，转而使用其它硬件失真工具。

这正是要继承 Unified V4 的地方。

禁止：

```text
完整 raw temporal encoder
Known enrollment tail memory
整个 open-set decision service
```

---

## Agent C：Open-Set Examiner

目标：

> 审查当前 Known 假设是否真正可信，或者是否应判为 Unknown。

允许的私有工具：

```text
Known enrollment prototypes
class distribution / robust scale
tail/open-space statistics
reconstruction evidence
identity-preserving consistency probe
historical intra-class variability
```

它不负责从 raw I/Q 再做一遍完整身份分类。

A/B 可以给它：

```text
candidate Tx7
competitor Tx12
public evidence
```

C 再检查：

```text
Tx7 是否真的位于正常 Known support？
是否只是“所有 Known 中最近的一个”？
当前身份是否对轻微扰动稳定？
重构/一致性是否异常？
```

# 4. 工具要是“模块”，Agent 才是“决策者”

代码中必须严格区分：

## Tool

工具是不会主动思考的函数/网络，例如：

```text
RawEncoder
ComplexEncoder
RobustSpectrumEncoder
ReconstructionTool
PrototypeDistanceTool
ConsistencyProbe
```

它们只接受输入并返回结果。

**不能把 Tool 叫 Agent。**

## Agent

Agent 负责：

```text
选择工具
解释结果
维护候选信念
决定是否还需要证据
主动发请求
处理别人发来的请求
根据新消息修改判断
```

这样可以避免以前：

> “每个网络模块都叫 Agent”

的问题。

# 6. Agent 内部需要“自主工具选择”，但第一版不要上强化学习

不要一开始就 PPO。

先用可监督的 counterfactual tool utility。

对每个训练样本，离线计算：

```text
只用 tool-1 的损失
只用 tool-2 的损失
tool-1 + tool-2 的损失
...
```

得到：

> 哪些工具对当前样本真正有帮助。

用这些反事实标签训练：

```text
ToolPolicy
```

让 Agent 学：

```text
当前样本调用哪个工具更有价值。
```

这样比单纯 softmax view gate 更接近自主决策，因为策略学习的是：

> **选择工具后能否改善自己的任务。**

第一版允许：

```text
SELECT_TOP1_TOOL
SELECT_TOP2_TOOLS
STOP_LOCAL_ANALYSIS
```

# 7. 工具选择不能读取 dataset name

统一禁止：

```text
if dataset == "ORACLE":
    ...
if dataset == "WiSig":
    ...
```

ToolPolicy 只能根据当前样本和本地状态选择工具。

我们真正希望看到：

```text
ORACLE 上模型自动少用 pure spectral
WiSig 上模型自动多用 spectral/difference
```

但这个差异必须是模型从样本中自主产生的，而不是代码写死。

# 8. 把 Unified V4 的优势变成新的 Agent 自主性实验

Stage-9 第一关不是通信。

先看每个 Agent 有没有自主工具选择能力。

必须报告：

```text
每个数据集的平均 tool usage
Known / proxy Unknown 的 tool usage
不同 SNR / 条件的 tool usage
每个样本 tool-selection entropy
```

尤其检查：

> 同一个 Agent 在 WiSig 和 ORACLE 上是否自动采用不同工具组合。

如果全部样本始终选择同一个工具：

> Agent 内部仍然没有真正自主性。

# 9. Agent 输出不能只是一套 logits

每个 Agent 统一输出：

```text
BeliefPacket
```

至少包括：

```text
candidate set
candidate evidence
uncertainty
open-risk opinion（若该 Agent 有权限）
used tools
reason code
request suggestion
abstain flag
```

注意：

`reason code` 不是自然语言必须项，可以是结构化枚举：

```text
LOW_MARGIN
TOOL_DISAGREEMENT
OUT_OF_SUPPORT
UNSTABLE_UNDER_PROBE
MISSING_IMPAIRMENT_EVIDENCE
```

这样 Agent 才能明确表达：

> 我为什么不确定。

# 10. 引入共享 Blackboard，而不是中央“赢家 Router”

新增：

```text
SharedBlackboard
```

它只保存公开状态：

```text
current candidates
published evidence
open-risk flags
questions
responses
conflicts
communication cost
```

它不能访问：

```text
private embedding
private tokens
private memory
tool hidden state
```

Blackboard 不做分类。

它只是通信介质。

# 11. 通信由 Agent 主动发起

每个 Agent 自己有：

```text
QueryPolicy
```

它决定：

```text
REPORT
ASK_IDENTITY
ASK_IMPAIRMENT
ASK_OPEN_SET
CHALLENGE
ABSTAIN
```

例如：

```text
Identity Agent：
Tx7 / Tx12 margin 很小
并且自己调用 raw+complex 后仍冲突
→ ASK_IMPAIRMENT(Tx7, Tx12)
```

而不是：

```text
Central Router：
A confidence 0.6，B confidence 0.7
→ 选 B
```

---

# 12. QueryPolicy 也先用反事实收益监督

训练阶段可以离线遍历：

```text
不询问的损失
询问 B 后的损失
询问 C 后的损失
```

得到：

```text
asking B 是否真正改善
asking C 是否真正改善
```

然后训练 Agent 自己的 QueryPolicy 预测：

> “我现在缺什么证据？”

这比训练一个中央 winner-selector 更符合多智能体。

---

# 13. 消息必须是语义证据，不传 private state

继续保留 Stage-8 已经做对的地方。

请求：

```text
QueryPacket
```

可以包含：

```text
candidate A
candidate B
question type
local uncertainty
reason code
```

响应：

```text
EvidenceCertificate
```

可以包含：

```text
support A / support B / unknown suspect / abstain
candidate-specific evidence
reliability
used tool family
```

禁止传：

```text
full embedding
full hidden state
full prototype table
full logits
```

---

# 14. 收到消息后必须真正修改 Belief

Stage-8 的 Candidate Evidence Table 应该保留。

例如：

```text
Identity：
Tx7 +1.2
Tx12 +1.0

收到 Impairment：
Tx7 -0.8
Tx12 +1.5
```

最终 Belief 必须改变。

测试必须保证：

```text
改 alternative candidate
→ 最终 candidate evidence 发生对应改变
```

不能重新退化成：

```text
整体降低 Agent A 权重
整体提高 Agent B 权重
```

# 15. Agent C 要吸收早期 Reconstruction 的价值

Stage-1 已经证明 Reconstruction 与 Identity/Prototype 会产生互补。

这部分不应该丢掉。

但 Reconstruction 不应再单独命名为一个 Agent。

更合理的是：

> Reconstruction 是 Open-Set Examiner 的一个私有工具。

C 可以自主决定：

```text
只查 prototype/tail
或
调用 reconstruction
或
做 consistency probe
```

这正符合“工具 ≠ Agent”的新定义。

# 17. Stage-9 Gate 设计

## G0：Agent 自主性

要求：

- 每个 Agent 的 ToolPolicy 不是常数；
- 不同样本会选择不同工具；
- WiSig / ORACLE 无 dataset branch，但 tool usage 自然不同；
- selected tools 相比随机/固定工具具有正 counterfactual utility。

不过 G0：

> 不做通信。

---

## G1：能力互补

检查：

- Identity unique rescue；
- Impairment unique rescue；
- OpenSet unique rescue；
- failure subset 是否不同；
- 不允许某个 Agent 近似覆盖其余全部功能。

如果某个 Agent 单独已经等价完整系统：

> 角色过大，必须拆边界。

如果某个 Agent 几乎永远无独特贡献：

> 角色过小或工具无效。

---

## G2：主动询问价值

固定 Agent 和 ToolPolicy。

比较：

```text
No communication
Random query
Confidence-based central selector
Agent-initiated query
```

要求：

> Agent-initiated query 稳定优于前三者。

---

## G3：消息因果性

必须做：

```text
messages off
message shuffle
wrong responder
wrong candidate pair
wrong reason code
```

正确通信应明显优于这些干预。

---

## G4：多智能体不可替代性

最终至少比较：

```text
Best single Agent
Three Agents no communication
Static multi-view fusion
Stage-5 Unified V4
Equal-parameter single-body adaptive multi-view
Stage-9 Full Multi-Agent
```

这是最关键的一关。

如果：

```text
Full Multi-Agent ≈ single-body adaptive multi-view
```

说明我们仍然没有证明多智能体的必要性。

# 21. 明确禁止重新踩的坑

下一阶段禁止：

### 坑 1：Super-Agent

一个 Agent 同时持有所有视图、Known memory、Unknown detector 和 Router。

### 坑 2：Micro-Agent

把 FFT、threshold、entropy、prototype 各自做成 Agent。

### 坑 3：固定 View = Agent

Agent 的角色应该是问题目标，不是固定输入类型。

### 坑 4：Central Winner Router

只根据 confidence 决定信谁。

### 坑 5：Dataset-specific Branch

手写 WiSig/ORACLE 两套逻辑。

### 坑 6：只追最终指标

必须同时证明自主性、互补性和通信因果价值。

# 22. 什么时候才允许继续复杂化

只有下面三条都成立：

1. Agent 内部工具选择确实随样本自适应；
2. 三个 Agent 存在稳定、不同的 unique rescue；
3. Agent 自己发起的 query 比随机/central-confidence query 更有效；

才允许：

```text
多轮 communication
更复杂 VOI
联合微调
多 seed
formal Unknown
```

否则继续改 Agent 定义，而不是加模型复杂度。

# 23. 下一阶段最终目标

我们要实现的不是：

> “三个网络分别算分，最后融合。”

而是：

> **三个具有不同私有资源的问题解决者。每个 Agent 能在自己的有限工具箱中自主分析；当自己的证据不足时，能够明确知道缺少哪一种知识并主动询问；被询问 Agent 针对具体问题使用自己的私有工具重新分析；新证据真正改变候选身份或 Unknown 判断。**

同时：

> 任何一个 Agent 都不能单独等价于完整算法。

这才是后续代码设计要验证的“真正意义上的多智能体开放集算法”。
