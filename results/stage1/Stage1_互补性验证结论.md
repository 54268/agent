## 2. 互补性是否成立（Stage-1 闸门）

| 判据 | WiSig | ORACLE | 结论 |
|---|---|---|---|
| 三证据最大 \|Spearman\| 相关（<1 即未 collapse） | 0.822±0.012 | 0.651±0.041 | 两数据集都明显 <1，**三 Agent 没有退化成一个** |
| Identity 漏检 Unknown 被几何/重构救援比例 | 0.404±0.030 | 0.597±0.051 | 立项动机场景**被复现**：高置信漏检由其他证据补救 |
| 三证据并集召回 vs 最强单证据召回 | 0.474 vs 0.306 | 0.793 vs 0.666 | **3/3 种子并集更高**，三通道抓的是不同 Unknown |
| 固定融合 AUROC 超最强单证据 | +0.009±0.008（2/3） | -0.002±0.005（1/3） | WiSig 多数成立；ORACLE 基本持平且受弱重构拖累 |
| 固定融合 OSCR / 覆盖 | 均值 OSCR 0.867；max 召回 0.474 | Prototype OSCR 0.913；max 召回 0.793 | 排序性能与固定阈值覆盖应分别报告，不能只用一个指标下结论 |

**总判定：三证据互补性成立，允许进入 Stage 2/3（Pseudo-Unknown + Communication）。** 互补性主要体现在
“检测覆盖/条件救援”和 max/OR 的固定阈值召回、H-score；AUROC/OSCR 最优规则依数据集而变。这正说明后续需要
**可学习 Router 按样本与证据可靠度加权**，而非固定等权平均（与设计文档第 18 章一致）。

## 3. 关键发现与踩坑（对后续阶段最重要）

1. **重构"学什么"决定成败。** 最初按文档 §9 重构共享特征 `h_s`，在 WiSig 有效（AUROC≈0.84），
   但在 Oracle 上反向（AUROC≈0.23）——未知发射机的 `h_s` 落入解码器覆盖区，"未知重构得比已知还好"
   （文档 §48.4 预判的"特征过于容易重构/方向不稳定"）。改为**类条件重构原始 IQ + 最难负类（最近竞争原型）
   重构裕度**后，WiSig 稳定在 0.83，Oracle 转正但偏弱（0.59）。
2. **Identity/Prototype 稳健，是主干证据**；类条件经验 CDF 校准（仅 Known 验证集）显著提升了稳定性，
   WiSig 三通道跨种子标准差均 ≤0.017。
3. **Oracle 存在"硬未知"**：未知 18/19/32 在特征空间极贴近某些已知类（最近原型距离 d1≈0.006–0.06、
   softmax 置信度 0.97–0.99），任何只用 Known 训练的证据都难分；未知 17/25/26 则几何上明显偏远，
   Prototype 即可抓住。这与上一方案"必须叠加伪未知生成 + 监督校准才能拿到 0.96+ 未知召回"的经验一致，
   **硬未知正是 Stage-3 Pseudo-Unknown Agent 的目标**，不应在 Stage-1 强求。
4. 校准/融合无需真实未知标签：类条件 CDF + max/OR 已能在不偷看未知的前提下显著扩大检测覆盖；但
   max/OR 不保证 AUROC/OSCR 最优，必须同时报告排序指标和固定阈值指标。
5. 修正后的单 seed Reconstruction CKA 为 WiSig：I-R=0.510、P-R=0.271；ORACLE：I-R=0.482、P-R=0.381。
   这些嵌入来自真实重构 bottleneck，可用于多样性诊断；旧随机投影 CKA 已废弃。

## 4. 下一步（Stage 2/3 建议顺序）

1. **先做 Pseudo-Unknown Agent（文档 §11/§14/§15）**，重点针对 Oracle 硬未知：边界挖掘
   （kNN 普通边界 + 分类面临界样本）+ 变换伪未知，且必须区分"真实未知/伪未知"两套校准，避免重蹈
   上一版跨域模型"伪未知验证集 AUROC≈0.999、真实未知≈随机"的覆辙。
2. **再做 Communication（§13）**：消息门 `m_i=σ(MLP([z_i,e_i,D_i]))`，先开 Identity↔Prototype↔Reconstruction
   全连接、预算损失关闭，验证加通信后条件救援/OSCR 是否进一步提升。
3. Router（§18）在固定 max/OR 已验证"按可靠度取证据"有效的基础上再学习权重；Boundary Agent 最后做。
4. 三证据在纯开放集跑通并稳定后，再逐步放回跨接收机/跨日期域变量（沿用上一版 P1→P2→P3）。
